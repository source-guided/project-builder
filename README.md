# Product Builder

작업 중 필요한 원천을 참조로 찾아 연결하고, 그 맥락에서 제품 작업을 이어가는 Codex 플러그인입니다. 기획·디자인·계약·코드·기존 결정이 어디에 있는지 찾고, 새 질문이나 변경이 생기면 관련 원천으로 돌아가 확인합니다.

이 흐름을 돕는 기본 스킬로 시작·재개, 요구사항 파악, UX, 구현, 검증을 제공합니다. 필요한 스킬을 작업 의도에 맞게 사용하며, 모든 작업을 고정된 단계나 한 번의 완료 과제로 만들지 않습니다. 특정 서비스·기술 스택·모델·작업 시간을 강제하지 않습니다.

## 설치

Codex CLI의 플러그인 기능이 필요합니다. 로컬 설치 검증 버전은 **0.153.4**입니다.

```sh
codex plugin marketplace add tkddu1591/product-builder --ref v0.3.0
codex plugin add product-builder@tkddu1591-tools
```

모델과 추론 강도는 사용자가 평소 쓰는 실행 환경에서 선택합니다.

활성화된 스킬은 “이 기능과 관련된 기획과 코드를 찾아줘”처럼 작업 의도로 선택됩니다. 명시적으로 시작할 수도 있습니다.

```text
$product-builder:start
이 기능을 수정하려고 해. 관련 원천과 기존 결정을 찾아서 작업을 이어가줘.
```

기존 작업도 같은 진입점으로 이어갑니다.

```text
$product-builder:start
지난 작업 이후 바뀐 요구사항과 코드를 확인하고, 지금 필요한 작업을 이어가줘.
```

설치 여부는 다음으로 확인합니다. 이미 열린 채팅의 스킬 목록이 자동으로 갱신됐다고 가정하지 마세요.

```sh
codex plugin list --marketplace tkddu1591-tools --json
```

공개 GitHub 저장소에서 설치하는 패키지이며, OpenAI의 공개 플러그인 디렉터리에 등록됐다는 의미는 아닙니다. 클라이언트별 플러그인 지원 여부와 필요한 도구 접근은 별도입니다.

## 작업 방식

[공통 참조 색인](plugins/product-builder/references/index.json)에서 요청과 관련된 영역을 찾고, 참조를 거쳐 실제 원천을 읽습니다. 원천에서 다른 원천이 필요해져도 참조로 주소를 확인하며, 독립적인 조회는 병렬로 진행할 수 있습니다. 디자인·프론트·프로젝트 사이의 수평 연결을 지원하며, 참조에는 위치·주제·접근 방식만 둡니다. 버전과 소유 정보도 별도 원천을 참조해 확인합니다. [참조 구조와 경로 검증](docs/reference-architecture.md)을 참고하세요.

탐색은 작업 시작 때 한 번 하고 끝내는 단계가 아닙니다. 구현 중 계약을 더 확인하거나, 변경된 디자인을 비교하거나, 다음 세션에서 기존 결정을 확인할 때도 같은 경로를 사용합니다. 원천은 각 소유자가 관리하며 프로젝트별 연결과 진행 상태는 해당 프로젝트에 둡니다.

| 스킬 | 맡는 일 |
| --- | --- |
| `start` | 현재 자료·환경·작업 상태를 확인하고 필요한 절차를 연결 |
| `brief` | README·기획·계약·인수 조건을 출처가 있는 요구와 검증 항목으로 정리 |
| `product-ux` | 사용자 과업, 정보 우선순위, 상태와 회복 흐름을 설계·검토 |
| `implementation` | 입력부터 관찰 가능한 결과까지 한 흐름씩 구현 |
| `verification` | 실제 요구에 맞게 기능·예외·UX를 확인하고 증거와 한계를 보고 |

단계마다 승인을 요구하지 않습니다. 자료로 해결할 수 없는 중요한 결정만 질문하고, 이미 허용된 구현·검증은 계속합니다. Git 게시·배포·외부 메시지는 별도 사용자 권한 범위에 따릅니다.

## 영역별 원천

기본 스킬의 구체적인 판단 기준은 각 영역의 원천이 소유합니다. README의 설명을 다시 정책으로 복제하지 않고 필요한 참조에서 실제 원천으로 이동합니다.

- [요구사항·구현·검증 참조](plugins/product-builder/references/delivery/index.json): 기획·계약 해석, 제약, 구현과 검증의 기본 기준
- [UX 참조](plugins/product-builder/references/design/ux/index.json): 사용자 과업, 정보 우선순위, 편집·선택·피드백 흐름
- [UI 참조](plugins/product-builder/references/design/ui/index.json): 접근성·컴포넌트 자료와 공통 화면 예제
- [Figma 참조](plugins/product-builder/references/design/figma/index.json): 디자인을 확인하고 작업에 연결하는 자료

실제 프로젝트의 기획·API·코드·결정은 소비 프로젝트의 참조에서 연결합니다. 기본 스킬과 예제는 프로젝트의 요구나 기존 owner 규칙을 대신하지 않습니다.

## 도구와 모델

기본 패키지는 스킬·예시·스크립트로 구성되며 자체 MCP 서버나 별도 서비스 인증을 요구하지 않습니다. 사용 중인 환경에 브라우저, Figma, 저장소 도구가 있으면 필요한 작업에 사용합니다. 도구가 없으면 가능한 확인을 수행하고 미검증 범위를 남깁니다.

플러그인은 모델이나 추론 강도를 선택하지 않습니다. 저장소의 선택적 평가 실행기도 기본적으로 사용자의 CLI 설정을 따르며, 호출자가 인자를 지정한 경우에만 해당 값을 전달합니다.

## 프로젝트 기록과 비공개 자료

공통 절차는 플러그인에, 실제 프로젝트의 요구사항·결정·검증·진행 상태는 해당 프로젝트에 둡니다. 기존 owner 문서가 있으면 이를 사용하고 중복 원본을 만들지 않습니다.

민감한 기록에 사용할 `.local/product-builder/`를 준비하는 선택적 스크립트가 포함되어 있습니다. 기존 기록을 덮어쓰지 않고 `.gitignore`에 `/.local/`를 추가합니다. 이미 추적 중인 파일까지 추적 해제하지는 않습니다.

이 저장소의 `.local/` 내용은 공개 패키지에 들어가지 않습니다. 배포 ZIP은 플러그인 디렉터리의 허용 파일만 포함합니다. 원천 자료를 외부로 보내거나 자동 업로드하는 기능은 없습니다.

공개 여부는 폴더명보다 특정 과제에 대한 의존성으로 구분합니다. 범용 하네스 자기개선 절차·입력 준비·모델 실행 도구와 도구 자체의 회귀 검사는 공개합니다. 개별 과제·데이터·전용 채점·답안·결과·프로젝트 참조는 합성 자료라도 사용하는 프로젝트 또는 무시된 `.local/`에 둡니다. 공통 UX 예제는 별도로 명시합니다.

## 플러그인 개발과 검증

아래는 플러그인 유지보수자를 위한 검사입니다. 일반 프로젝트 작업의 시작 절차나 시간 제한이 아닙니다.

Python 3.9 이상, 표준 라이브러리와 Git으로 패키지 검사를 실행할 수 있습니다.

```sh
python3 scripts/validate.py
python3 -m unittest discover -s tests -v
python3 scripts/package.py
```

공개 UX 예제의 브라우저 회귀 검사에는 Node.js 22와 Playwright 개발 의존성을 사용합니다. 플러그인을 사용하는 프로젝트에 이 의존성을 설치할 필요는 없습니다.

```sh
npm ci
npx playwright install chromium
npm run test:ui
```

공통 UI 예제의 회귀 범위와 증거 구분은 [검증 문서](docs/validation.md)에서 관리합니다.

[하네스 자기개선 절차](docs/forward-testing.md)에 따라 개별 평가를 로컬에서 실행합니다. 범용 준비 도구 `scripts/prepare_eval.py --input <원본 입력 폴더> --output <새 작업 폴더>`는 소비자가 제공한 자료만 전달합니다. 구현자에게 줄 요구와 입력에서 정답·평가표·이전 산출물을 분리합니다. 사용자 추가 요구는 `--context`로 별도 보존할 수 있습니다. `scripts/run_eval.py --review`는 독립 검토를 연결하고 실제 실행 리비전과 증거를 확인합니다. 패키지 검사, 모델 행동, 제품 실행, 실제 배포·사용자 인수는 구분합니다.

## 구조

```text
.agents/plugins/marketplace.json   # GitHub 배포 소스
plugins/product-builder/
  plugin.json                     # 설치 패키지
  references/                     # 범주별 탐색 메타데이터와 수평 연결
  sources/governance/              # 별도 소유한 참조 탐색 원칙
  scripts/references.py            # 발견·관리·세션 실행 CLI
  scripts/reference_*.py           # 무상태 발견, 접근 어댑터, 관리, 세션, 실행 정책
  skills/                         # 진입점과 각 영역이 소유하는 실제 절차
scripts/                          # 구조·배포·범용 하네스 자기개선 도구
tests/                            # 파일 보존·배포 경계 등의 검사
.local/                           # 비공개 기록·실행 증거, Git 제외
```

패키징 형식은 [OpenAI 공식 문서](https://developers.openai.com/plugins/build/plugins)를 따릅니다. MIT License.
